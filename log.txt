    Implements complete PostgreSQL support alongside existing SQLite functionality,

    ## Features Added
    
    ### Database Support
    - Runtime database type detection from connection string
    - SQLite: file paths or sqlite:// URLs (auto-creates database file)
    - PostgreSQL: postgres:// URLs (auto-creates database if missing)
    - Enum-based pool wrapper for compile-time safety without runtime overhead
    
    ### Migration System
    - Separate migration directories for each database type
      - migrations/ - SQLite migrations (INTEGER, AUTOINCREMENT)
      - migrations_postgres/ - PostgreSQL migrations (BIGINT, BIGSERIAL)
    - Auto-detect and run appropriate migrations on startup
    - Full schema parity between both databases
    
    ### Database Operations
    - All write operations use database-specific UPSERT syntax
      - SQLite: INSERT OR REPLACE
      - PostgreSQL: INSERT ... ON CONFLICT ... DO UPDATE
    - All read operations handle different parameter placeholders
      - SQLite: ? for all parameters
      - PostgreSQL: \$1, \$2, \$3... for positional parameters
    - Row processing within match arms to handle different row types
    
    ### CLI Updates
    - Updated --cache-db help text with PostgreSQL examples
    - Supports -d, --cache-db, --database flags
    - Environment variable CACHE_DB works with both database types
    
    ## Implementation Details
    
    Uses DatabasePool enum wrapping SqlitePool and PgPool:
    - Provides compile-time type safety
    - Zero runtime overhead (no trait objects or vtables)
    - Pattern matching for database-specific SQL syntax
    - Process rows within match arms due to SqliteRow vs PgRow types
    
    ## Testing
    - ✅ SQLite: Fully tested with auto-creation and migrations
    - ✅ PostgreSQL: Tested with local server
      - Auto-creates database if it doesn't exist
      - Runs migrations correctly

      - All data types handled correctly
